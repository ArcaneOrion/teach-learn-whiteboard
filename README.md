# 共写白板 · 安卓学习工具

一个装在安卓手机/平板上的本地白板应用。你在板上写字、画图，AI 也在同一块板上写讲解、出题、批注；
你可以直接在它写的东西上圈画，而**它能看见你圈了什么**。

> **当前状态：v1 功能完整、可运行、有 326 个单元测试。**
> M0~M7 八个里程碑全部实现并验证过（见下方「实现进度」）。
> **还没做的一件事：打包成 APK**（本机缺 JDK / Android SDK，见 `docs/安卓构建环境.md`）。

---

## 先跑起来

```bash
pnpm install     # 装依赖（只需一次）
pnpm dev         # 启动开发服务器
```

终端会打印一行局域网地址（形如 `http://192.168.x.x:5173/`）——
**手机连同一个 Wi-Fi，浏览器打开它，就能真的用笔在上面写。**

想看做出来的 App 长什么样（生产构建）：

```bash
pnpm build       # 类型检查 + 打包
pnpm preview     # 起一个本地服务器预览 dist/
```

> 开发模式自带一个「本地演示（假模型）」渠道，**不用 API Key 就能把整条流程走一遍**。
> 生产构建里没有它 —— 那时需要自己配一个渠道（见下）。

## 怎么用

### 1. 配一个模型渠道（用 AI 才需要）

点工具栏的 **⚙️ 渠道** → 填四项：名称、Base URL、API Key、模型 ID。

| | |
|---|---|
| 例子 | `DeepSeek` · `https://api.deepseek.com/v1` · `sk-…` · `deepseek-chat` |
| 任何 OpenAI 兼容端点都行 | Ollama、硅基流动、OpenRouter…… |
| **Key 只在这台设备上** | 这个 App 里没有上传 Key 的代码，请求从你的设备直连厂商 |

浏览器里能直连的厂商（实测见技术文档 §7.3）：
DeepSeek / 硅基流动 / 智谱 / 通义 / xAI / Anthropic（需额外请求头）。
OpenAI、OpenRouter、Moonshot、Google 被 CORS 挡住，**装成 App 之后走原生网络才能用**。

### 2. 学

- **写、画、圈**：直接在板上用笔或手指
- **打字问它**：底部输入条
- **它跑太久可以在中途停下**：运行中「发送」会变成 **⏹ 停止**
- **让它看你的笔迹**：点 **👁 让 AI 看** → 拍下当前板面 → 写上你想说的 → 发送
  （一次同时传达三件事：板面长什么样、你圈了哪、你想说什么）
- **滚动板面**：两指滑动，或切到 **✋ 拖动**
- **给 AI 表态**：长按它写的那一块 → 👍 / 👎 / ❌

### 3. 找得回来

点 **🕘 记录**：上面搜索，下面是按日期分组的会话。
搜得到板面内容、你说的话、**截图**（截图靠"你当时打的那句话"+ AI 生成的图说被搜到）。
点搜索结果会跳到板上对应的那块并高亮。

### 4. 上传资料让 AI 去查（RAG）

点 **📚 资料** → 导入 `.txt` / `.md` / **`.pdf`**。
之后问它相关问题时，它会**自己去查**，把查到的**原文 + 出处（书名 / 第几页）**写到板上。

> 定位是「**让 AI 去检索你上传的文件**」，不是「把整本书塞进上下文」。
> 扫描版 PDF 读不出文字（整页是图片）—— 那种还没做。

### 5. 多块板

点 **🗂 板**：一块板 = 一个主题。可以切换、新建、改名、删除。
**切板不会新开一次学习** —— 同一次学习里可以翻好几块板。

### 6. 备份与同步

点 **💾 数据**：

- **导出备份**：数据存在设备本地，**卸载即删**，所以导出是必需功能
- **从备份恢复**：合并式导入，同一个文件导两次也不会重复
- **存成图片**：把当前这块板存成 PNG（**内容和你的笔迹都在里面**），可以发人、贴笔记、打印
- **同步**：见下面「同步服务」

> 备份文件里**不含 API Key**（这是刻意的，见 `docs/技术开发文档.md` §11.0 附近的说明）。

## 开发

```bash
pnpm dev          # 开发服务器（改代码自动刷新）
pnpm test         # 单元测试
pnpm typecheck    # 只做类型检查
pnpm build        # 类型检查 + 打包到 dist/
pnpm preview      # 预览生产构建
pnpm sync-server  # 起同步服务（默认 8787）
pnpm sample-pdf   # 生成一个测试用的 PDF
```

`pnpm dev` 和 `pnpm build` 会先跑 `scripts/sync-pdfjs-assets.mjs`，
把 pdf.js 需要的 CMap 资源复制到 `public/pdfjs/`（**中文 PDF 靠它才能抽出文字**）。
那 2.5 MB 不进 git。

### 同步服务

```bash
pnpm sync-server                              # 默认起在 8787，数据存 ./sync-data.json
pnpm sync-server --port 9000 --token 你的口令  # 换端口 / 加口令（口令只能用 ASCII）
```

然后在 App 里「💾 数据」→ 填地址 → 立即同步。多台设备填同一个地址就能互相对上。

**打开「自动同步」之后不用管它**：写了东西停手 20 秒就自动传上去，平时每 5 分钟看一眼有没有别的设备写的新内容。
（`auto` 默认开 —— 填了地址多半就是想让它是自动的。离线时会安静重试，不弹错。）

⚠️ 这个服务是**给你自己用**的：没有账号体系、数据是明文 JSON。
只在自己机器 / 局域网里跑，别直接暴露到公网。要公网用就加 `--token` 再套一层 HTTPS 反代。

### 出怪事时先试这个

**改了代码但页面行为没变、或者报「某某函数不存在」** → **重启 `pnpm dev`**。

踩过的坑：Vite 的**模块转换缓存**有时不会跟着文件改动失效（文件监听漏了），
于是浏览器拿到的是「编辑做到一半」的版本 —— 一半新一半旧，报错信息完全对不上源码。
**这时候刷新页面没用，必须重启 dev server。**

### 验窄屏布局（手机才是主要设备）

单元测试**测不出布局问题**（jsdom 不做排版）。最省事的办法是**在浏览器控制台里塞一个 390px 宽的 iframe**：

```js
const o = document.createElement('div');
o.style.cssText = 'position:fixed;inset:0;z-index:9999;background:#eef1f5;padding:10px';
const f = document.createElement('iframe');
f.src = location.origin + '/';
f.style.cssText = 'width:390px;height:780px;border:1px solid #ccc;background:#fff';
o.append(f); document.body.append(o);
```

然后查有没有横向溢出：

```js
const d = f.contentDocument;
console.log(d.documentElement.scrollWidth, d.documentElement.clientWidth);
```

两个数不一样就是溢出了 —— 再用这个找出是谁撑宽的：

```js
[...d.querySelectorAll('*')].filter(e => e.getBoundingClientRect().right > d.documentElement.clientWidth + 1)
  .map(e => e.tagName + (e.id ? '#' + e.id : '') + ' ' + Math.round(e.getBoundingClientRect().width));
```

> **必须看一眼截图，不能只看数字。** 至今抓到的几个最麻烦的 bug（截图丢笔迹、
> 存储退回内存、工具栏被挤成竖排），读数全都是"正常"的。

## 四句话总结

1. **形态**：共写画布 —— 板是唯一界面，AI 说的话直接写进板里，不做「聊天框 + 白板」两栏。
2. **技术**：只用 TypeScript 一种语言。Web 技术画白板，`@earendil-works/pi-ai` 接 AI，Capacitor 打包成安卓 App。
3. **数据**：一切以「只追加的事件日志」为唯一真相 —— 同步、撤销、学习记录、检索都从它白拿。
4. **组织**：**板 = 主题**（长期），**会话 = 一次坐下学习**（有始有终），两者正交。
   **整个 App 不要任何危险权限，装完不弹框**；代价是**卸载即删**，所以导出备份是必需功能。
