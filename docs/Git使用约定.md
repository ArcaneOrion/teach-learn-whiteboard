# Git 使用约定

> 面向「代码小白」写的最小必要 git 规范。**你只需要记住 6 个命令和 5 条铁律。**

---

## 为什么这个项目要专门讲 git

因为你是**一个人**在做一个**会持续几个月**的项目。git 对团队协作的价值你用不上，
但对你有一个不可替代的作用：

> **它是你的后悔药。** 改坏了能退回去，试错了不怕，敢动手。

一个人做项目最容易死在「不敢改」——因为怕改坏了回不去。有了 git，这个恐惧就消失了。

---

## 五条铁律

### 铁律一：动手改之前，先提交一次

```
git add -A && git commit -m "改之前的状态"
```

这样改坏了一句话就能退回来。**这是最重要的一条。**

### 铁律二：小步提交，不要攒

每完成一件**能说清楚的小事**就提交一次。
不要攒一天的改动一次性提交 —— 那样出问题时你分不清是哪一步搞坏的。

**判断标准**：能用一句话说清「这次做了什么」就该提交了。

### 铁律三：提交信息写「为什么」，不只写「改了什么」

```
❌ 修改了 board.ts
✅ 事件折叠忽略了 ink.clear，导致清空画笔后笔迹会复活
```

第二种写法，三个月后的你能看懂，AI 助手也能看懂（你让我帮你排查问题时，我会先看提交历史）。

### 铁律四：密钥永远不进仓库

`.gitignore` 里已经挡住了 `.env`、`*.jks`、`*.keystore`。
**但你要知道为什么**：仓库一旦推到公开平台，密钥就等同于泄露；安卓签名密钥泄露，
别人可以冒名发布"你的" App。

如果你不小心提交了密钥：**立刻作废那个密钥**（去服务商后台删掉重建），
光删文件是没用的 —— 历史记录里还在。

### 铁律五：里程碑打标签

每完成一个里程碑（M0、M1…），打一个 tag：

```bash
git tag -a m0-能画线 -m "M0 完成：手机上能画线，不弹权限框"
```

这样将来任何时刻你都能回到「M0 那个能跑的版本」，对比看后来改了什么。
**对小白特别有用**：新功能搞砸了，先回到上个 tag，再慢慢试。

## 你只需要记住这 6 个命令

| 命令 | 干什么 | 什么时候用 |
|---|---|---|
| `git status` | 看现在有哪些改动 | **任何时候，最常用的一个** |
| `git add -A` | 把所有改动放进"待提交" | 提交前 |
| `git commit -m "说明"` | 提交 | 完成一件小事后 |
| `git log --oneline` | 看历史 | 想知道之前干了啥 |
| `git diff` | 看具体改了哪几行 | 提交前想确认一下 |
| `git restore <文件>` | 放弃某个文件的改动 | 改坏了想撤销 |

**其它命令你现在都不需要学。**

---

## 出事了怎么办

### 场景一：改坏了，想退回上次提交

```bash
git restore .            # 放弃所有未提交的改动（危险：改的东西没了）
git restore src/board.ts # 只放弃某个文件
```

⚠️ 这会**永久丢弃**你还没提交的改动。所以铁律一才那么重要。

### 场景二：想回到某个里程碑看看

```bash
git log --oneline        # 找到那个提交的编号
git stash                # 先把当前改动收起来
git checkout <编号>      # 过去看看（看完用 git checkout main 回来）
```

### 场景三：提交了不该提交的文件

```bash
git rm --cached 文件名    # 从 git 里移除，但保留磁盘上的文件
```

然后把它加进 `.gitignore`。

## 本项目的分支策略：不用分支

一个人开发，**直接在 `main` 上提交就好**。

分支是为了多人并行，你用不上，反而增加负担。
等哪天要做「一个不确定能不能成的大改动」时，我们再谈分支。

## 和 AI 助手配合的约定

每次你让我帮你写代码或排查问题时，我会：

1. **先看 `git status`** —— 确认工作区干净，避免把你的改动卷进去
2. **一次只改一件事** —— 让你能看懂每一步，也能单独回退
3. **改完提示你提交** —— 并给你一句可以直接用的提交信息

你要做的只有一件事：**我说"建议提交"时，真的去提交。**
不然改了几轮之后，就分不清哪次改动导致了哪个问题了。

## 给这个项目定好的提交前缀

为了历史记录好读，提交信息用这几个前缀开头：

| 前缀 | 用在 |
|---|---|
| `文档:` | 改文档 |
| `功能:` | 加新功能 |
| `修复:` | 修 bug |
| `重构:` | 改结构但不改行为 |
| `基建:` | 环境、依赖、配置、打包 |
| `实验:` | 试试看，可能推翻 |

例：

```
基建: 初始化 Vite + TypeScript 工程
功能: 白板支持手写笔与手指绘制
修复: 事件折叠忽略了 ink.clear，清空后笔迹会复活
文档: 补充存储权限说明与卸载风险
```
